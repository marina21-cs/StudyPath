## Existing build-specific evidence

The project's 4 November verification record reports:

- Local build and **472 JVM tests**, zero failures, errors, or skips.
- Local native registration, preferences, Saved, Planner, account, logout and relogin smoke.
- Setup navigation retaining an entered draft when moving back.
- Cloud build using the same application source with different Firebase constants.
- In-place update from 0.1.1 to 0.1.2 retaining an owned test marker.
- Launcher icon and compact Welcome checks.

During GitHub packaging, `sha256sum`, SDK 36 `aapt dump badging`, and `apksigner verify --verbose --print-certs` independently confirmed the existing APK's checksum, version, Android requirements, debug status, and valid v2 signature. No application code was changed or new device test claimed for publication. Raw reports and account/device data remain local.

## Known limits

The hosted lesson catalog is empty. No learning content or database rules were published as part of packaging. The original physical-phone failure and legacy-cache recovery remain unverified. The local smoke does not establish live cloud registration, full accessibility, physical performance, real 48-hour retention, or final project acceptance. Lesson-objective disclosure and disabled-motion/large-font/TalkBack cases were not separately repeated in the final native smoke.

The source checkout defaults to local Firebase emulators. Building an equivalent cloud APK requires your own ignored Firebase client configuration. Signing keys are not distributed in the repository.
